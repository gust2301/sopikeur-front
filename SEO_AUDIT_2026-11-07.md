# Audit SEO Sopiker — 7 novembre 2026

## État et mesures vérifiés

Audit effectué dans la Search Console connectée de `sc-domain:sopikeur.sn`, sur le site public et dans le dépôt frontend. Les modifications décrites ici sont locales, pas encore déployées. Aucune validation de correction ni demande d'indexation n'a été soumise avant publication.

Sur la période affichée du 5 août au 4 novembre 2026 : 206 clics, environ 1 890 impressions, CTR 10,9 %, position moyenne 7 (tous pays et toutes requêtes). Sénégal : 179 clics et 1 644 impressions. La position moyenne globale ne signifie pas une 7e place sur chaque mot-clé au Sénégal.

Indexation (rapport actualisé au 23 octobre) : 25 pages indexées, 18 exclues. HTTPS : 23 URL HTTPS et aucune non HTTPS ; données Core Web Vitals insuffisantes, ce qui ne prouve pas que les performances sont bonnes.

## Corrections réalisées dans le dépôt

- Accueil : ajout d'un H1 explicite « Sols SPC et panneaux acoustiques au Sénégal », mention de Sopiker/Sopi Kër, Dakar et Saly ; correction de « accoustiques ».
- Produits : titres et descriptions individuels, métadonnées sociales et JSON-LD Product/Offer, prix issu de l'API en XOF, disponibilité issue du catalogue. Aucun faux avis ou engagement commercial ajouté.
- Articles : canonique avec slash final, métadonnées sociales et JSON-LD BlogPosting avec date de publication réelle.
- Pré-rendu : ajout des routes dynamiques des 11 produits et 4 articles ; contenu et métadonnées présents dans le HTML avant exécution JavaScript.
- Sitemap : 31 URL canoniques (16 pages statiques, 11 produits, 4 articles), générées depuis les API publiques ; liste partagée avec le pré-rendu.
- Maillage : liens HTML explorables à la place des boutons de découverte sur l'accueil et les produits associés ; liens des catalogues et articles alignés sur le slash canonique.
- Panier, précommande, suivi de commande : directives noindex dans les métadonnées ; en-têtes Cloudflare Pages complémentaires pour ces chemins. Aucun chemin de suivi privé dans le sitemap.
- Identité : nom et variantes Sopiker/Sopi Kër/Sopi Keur/Sopikeur reliés dans les données de l'entreprise, pays de service Sénégal.
- Vérification automatisée du HTML de production : canonique exacte, titre unique, un H1, absence de noindex sur les pages du sitemap, JSON-LD produit/article valide et noindex sur panier/précommande.

## Validation locale

Compilation Angular de production réussie sous Node 20. Le projet avait un binaire esbuild Intel et un Node 26 ARM local : vérification effectuée avec un Node 20 temporaire et le binaire esbuild déjà installé, sans modification du lockfile. `.nvmrc` fixe Node 20 pour le projet.

`npm run seo:verify` valide les 31 pages du sitemap et les liens produits présents dans le HTML initial de l’accueil. Le contrôle visuel local confirme le nouveau H1 et la mise en page ; les API et médias distants ne se chargent pas tous depuis localhost, donc le contrôle interactif complet devra être répété sur le domaine de préproduction ou de production. Angular produit aussi les routes statiques découvertes automatiquement. Avertissement restant : feuille SCSS de l'accueil de 7,71 ko pour un seuil d'avertissement de 6 ko ; pas d'échec de compilation.

## Mise en ligne et suivi Search Console

1. Relire les changements, puis publier le frontend via le flux Cloudflare Pages existant. Configurer la commande de production `npm run build` et le répertoire `dist/frontend/browser`. Un simple `ng build` utilise les routes déjà enregistrées, mais ne régénère pas les nouveaux produits/articles et ne lance pas les contrôles postbuild.
2. Après publication, contrôler accueil, catalogues, une fiche produit et un article : réponse 200, contenu dans le HTML brut, titre propre, canonique unique avec slash. Contrôler aussi les en-têtes noindex des pages transactionnelles.
3. Contrôler les redirections HTTP et www vers HTTPS sans www, puis les redirections des variantes sans slash. Éviter les chaînes inutiles. Garder les exclusions normales dans Search Console.
4. Vérifier que le sitemap public contient les 31 URL ; le renvoyer dans Search Console, puis utiliser l'inspection en direct et demander l'indexation des pages prioritaires modifiées. Tester Product/BlogPosting avec Rich Results Test. L'existence du JSON-LD ne garantit pas un résultat enrichi.
5. L'endpoint Cloudflare 404 n'a pas de page équivalente : ne pas le rediriger vers l'accueil pour masquer le signal. Le blocage de crawl n'est pas une preuve de validation de correction. Le compteur historique peut persister.
6. Les prix, stocks et articles pré-rendus sont des instantanés : reconstruire après toute modification du catalogue ou des publications. Programmer une reconstruction dans le système de publication si besoin ; aucune automatisation n'est créée par cet audit.

Le formulaire d'édition n'a pas chargé dans l'interface automatisée : aucune modification de fiche effectuée.

- Aligner l'URL du site sur `https://sopikeur.sn/` (le lien observé dans le DOM de la fiche utilise www).

- Enrichir les pages SPC et panneaux avec prix à jour, unité m²/pièce, frais et délais de pose/livraison vérifiés, conditions du devis, photos de réalisations locales.
- Prioriser les requêtes déjà observées : « pvc sol dakar » (57 impressions, 3 clics), « revetement de sol » (86 impressions, 1 clic), « panneau acoustique » (22 impressions, 4 clics). Travailler aussi « sol SPC Sénégal », « prix sol SPC Dakar » et « panneaux acoustiques Dakar » ; ces dernières sont des cibles, pas des positions mesurées.
